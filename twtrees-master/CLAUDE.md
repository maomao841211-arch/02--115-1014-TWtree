# 專案協作規範(多模型分工)

本專案採用「指揮官 + 專職 subagent」架構。主 session(指揮官)負責規劃與委派,
盡量不親自進行大量檔案修改;實際工作交給對應模型的 subagent。

## 角色與模型分工

| 角色 | subagent | 模型 | 職責 |
|------|----------|------|------|
| 指揮官 | (主 session) | Fable | 拆解任務、決定委派對象、彙整結果、最終決策 |
| 執行 | coder | Sonnet | 實作、修 bug、寫測試、重構 |
| 前處理 | data-prep | Haiku | 資料清洗、格式轉換、拆檔、批次重新命名 |
| 複核(外部) | codex-reviewer | Haiku(殼)+ 外部 Codex | 用 Codex 對變更做獨立審查,不改檔 |
| 複核(原生) | reviewer | Opus | 從 Claude 視角獨立審查變更,不改檔 |

## 委派決策

指揮官在動手前先判斷任務性質:

1. 需要大量清洗、拆分、轉檔、批次改名 → 先派 **data-prep**。
2. 需要寫或改程式、修 bug、補測試 → 派 **coder**。
3. coder 完成且準備 commit 前 → 同時派 **codex-reviewer** 與 **reviewer** 平行複核,指揮官再比對兩邊。
4. 只有純規劃、架構判斷、跨結果彙整 → 指揮官自己處理,不委派。

## 標準工作流

一個典型任務照這個順序跑:

```
規劃(指揮官)
  → data-prep(如有前處理)
  → coder(實作)
  → codex-reviewer ∥ reviewer(雙視角平行複核)
  → 指揮官比對兩邊、彙整並回報
```

- coder 不做架構決策;遇到規格不清就回報指揮官,不自行假設。
- data-prep 不做程式邏輯判斷,只做機械性處理。
- 兩位複核者各自獨立審查,**不參考對方結論**,以維持視角互相獨立。
- 指揮官需比對兩邊發現,標出「一致」與「分歧」;分歧項不可忽略,需再確認或請使用者裁決。
- 只要任一方回報 CRITICAL / HIGH,指揮官就把問題退回 coder 修正,再複核一次,才算完成。

## 護欄

- 任何刪除、權限變更、對外送出的動作,指揮官先向使用者確認再進行。
- subagent 回報保持精簡:只回結論、產出路徑、待決事項,細節留在自己的 context。
- 若 Codex 不可用(未安裝或未登入),codex-reviewer 應明確回報「Codex 未就緒」,不要靜默略過複核。
